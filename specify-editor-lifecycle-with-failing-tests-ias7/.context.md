## Goal

Make the shared editor/terminal acceptance and completion lifecycle executable before changing production code.

## Work

Add or invert focused tests in `workbook-attempts.test.ts`, `workbook-block-progression.test.ts`, `workbook-terminal.test.ts`, `activity-band.test.tsx`, and `workbook-ui.test.tsx` for the four states described by the parent Yak.

The tests must prove:

- acceptance does not imply completion, read-only presentation, frozen history, or activity-band removal;
- accepted editor and terminal surfaces stay live, sticky, and interactive;
- a newer editor revision or terminal command temporarily removes completion eligibility;
- the newest attempt can be accepted and restores eligibility without duplicate work acceptance or authored rows;
- completion moves accepted evidence from the sticky live surface to exactly one read-only historical surface;
- restart preserves accepted-active and completed-history state.

Preserve explicit regression assertions for reflection accepted-attempt protection, editor focus/cursor and debounce, xterm/WebSocket identity, stale editor/terminal response ordering, fatal state, no historical submission/reconnect/autofocus, and no duplicate feedback or Continue controls.

## Deliverable

Commit tests that fail for the confirmed reasons on the current implementation. Do not weaken assertions merely to accommodate existing behavior. Record the focused failing command and failure summary in the handoff. Do not modify production code.

## Goal

Keep accepted but incomplete editor and terminal surfaces visible, sticky, and interactive.

## Work

- Remove accepted-practice early returns from activity-surface selection and `ActivityBand`; completion alone releases the live surface.
- Derive completion only from authoritative block completion.
- Keep an active editor mounted and editable during editing, review, feedback, and accepted states unless fatal state disables mutations.
- Keep the same xterm and WebSocket mounted with stdin enabled during running, checking, feedback, and accepted states.
- Present accepted success feedback in the welded bar without replacing either surface.
- Keep exactly one Continue control only while the current attempt is accepted.
- Preserve CodeMirror identity, focus/cursor, local text, debounce, terminal transport identity, terminal insertion registration, and stale-response guards across asynchronous acceptance.
- Post-acceptance editor edits and terminal commands must enter the ordinary current-attempt review lifecycle and reflect withdrawn/restored completion eligibility.

## Constraints

Do not autofocus because acceptance arrives. Do not regress fatal-state read-only handling or ready-terminal preload/promotion behavior.

## Deliverable

Make accepted-active browser and activity-band tests pass and commit the focused UI changes with test evidence.

Add a read-only editor-style workbook surface for inspecting an authored file from the active live workspace. The pixel-creature lesson uses it to show the shared spec.md without asking the learner to author or submit the seed.

Prefer an explicit read-only file-view block or mode rather than abusing editor-practice and auto-accepting unchanged text. It should use the same workspace/path boundary protections as editor targets, load server-authoritative file content, render with the editor visual language and appropriate syntax/plain-text mode, expose no save/review endpoint, and progress with the ordinary Continue mechanism.

Acceptance:
- The learner can scroll, select, and copy spec.md but cannot edit it.
- The view is clearly labelled read-only and shows the workspace-relative path.
- Missing/unsafe paths fail during authored-content validation or session startup, not as a broken browser surface.
- File contents do not leak from sibling workspaces or session metadata.
- Reload and narrow/expanded activity layouts are stable.
- Contract, server, UI, accessibility, and layout tests cover the new surface.

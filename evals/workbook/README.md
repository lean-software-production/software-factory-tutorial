# Authored workbook evaluator

Root-owned evaluator code for the authored learner workbook lives here. It is separate from the synthetic tutorial-engine mechanics evals under `tutorial-engine/evals/`.

`command-stubs.ts` provides deterministic Pi/npm command stubs for post-Lesson-001 authored scenarios. The stubs are designed for later authored scenario-runner integration. They materialize generated bin/state/evidence under the disposable session workspace's ignored `factory/.tmp/authored-eval-command-stubs/`, which will be visible as `/workspace/factory/.tmp/authored-eval-command-stubs/` through the canonical Docker bind mount.

`scenarios.ts` declares the four authored release journeys, their honest curriculum slices, exact artifact allowlists, prerequisite seeds, deterministic gates, and conservative `expectedModelCalls` budgets. `run.ts` creates a fresh selected slice and normal session for every scenario repetition and creates command stubs only for post-Lesson-001 scenarios.

The runner uses the normal embedded Docker terminal boundary. Stub activation is a driver-private terminal prefix applied only to WebSocket input bytes; scenarios submit logical learner commands, and the prefix is stripped from recorded state, transcripts, traces, prompts, reports, and latest metadata. Evidence and config inside the learner mount are untrusted corroborating gate inputs: gates cross-check them against the workspace, internal raw timeline, source/Git facts, public JSON/RPC traces, and allowlisted projections, never treat them as sole authority.

`public-trace.ts` rebuilds the judge-visible trace from learner-visible state, terminal transcript, reflection turns, editor status, projected progression events, and explicitly allowlisted artifacts. Keep raw timeline rows, command/evidence IDs, Tutor or Coach prompt text, credentials, and disposable paths out of public prompts and reports.

`judge.ts` and `reports.ts` provide the privacy-safe judge prompt, result validation, verdict rule, lifecycle metadata, latest-report envelope, stability aggregation helper, and per-run report bundle. Scenario code must pass a rebuilt public descriptor with only `id`, `title`, `description`, and unique public criteria. Successful runs build the complete curated bundle in memory, defer publication until cleanup succeeds, then transactionally write exactly these ignored artifacts under `evals/workbook/reports/<run-id>/`: `trace.json`, `judge-input.json`, `judge.json`, `report.json`, `summary.md`, and `metadata.json`. Any setup, session, gate, judge, report, cleanup, or interrupted failure writes only sanitized marked `metadata.json`; if cleanup fails after an otherwise passing run, the public lifecycle is a cleanup failure with only failure metadata. Deterministic gate output, stack traces, cleanup leaks, raw commands, prompts, responses, and paths belong only in local diagnostics. Local diagnostics such as `gate.json`, `failure.txt`, and `cleanup-failure.txt` may contain private details and must not be advertised in curated metadata/latest or published. The invocation-level `evals/workbook/reports/latest.json` is replaced atomically after a batch with only attempted runs, exact status-derived file sets, and constrained relative report directories (`<run-id>` or `runs/<run-id>`).

`preflight.ts` exposes `runAuthoredWorkbookEvalPreflight()`. `run.ts` calls it exactly once for the selected IDs and repeat count before creating report roots, run IDs, workspaces, sessions, stubs, or judge inputs. It accepts scenario IDs, model identities, environment, and an explicit budget; production validation resolves those IDs against the frozen `AUTHORED_WORKBOOK_SCENARIOS` catalog and never trusts caller-supplied scenario objects, role counts, flags, or prompts. It validates arguments and total paid-call/token budget first, checks npm and the production Docker daemon/image primitive, creates a disposable canonical-calculator workspace with real authored command stubs, starts the workbook terminal, proves the generated stub PATH/config/evidence layout inside `/workspace` via private Docker stdin rather than argv, checks Pi auth, removes the terminal and fixture, then spends the paid Main Tutor, Practice Coach, and configured Judge preflight calls.

CLI parsing validates `--scenario` IDs against the authoritative catalog by default and carries only IDs into the request; a clearly named test-only catalog seam exists for parser/unit tests. The parser never accepts call counts from CLI values and never fabricates unknown/default scenarios. Public preflight output is allowlisted to scenario IDs, public model identities, structural judge command details, aggregate counts, and a token-spend warning. Do not include prompts, responses, credentials, raw command diagnostics, custom command absolute paths, Docker output, or disposable absolute paths in public errors or summaries.

Run the live evaluator with `npm run eval:workbook -- --scenario <exact-id> ...`, `npm run eval:workbook -- --all --yes ...`, or `npm run eval:workbook -- --release ...`. Use `--list` to print catalog IDs without npm/Docker/model/report side effects. Live scopes require the preflight model flags or matching environment variables plus `--max-paid-model-calls` and `--max-estimated-tokens`; release runs all four scenarios once in catalog order. `--keep-workspace` is private-debug only for one non-release scenario at repeat 1; the absolute path is warned on the console and never enters reports/latest.

All external operations are injectable so tests run without Docker, network, or model calls. Fixture creation uses an abortable partial-lease cleanup path so a timeout removes partially populated roots and command-stub handles before paid probes can run.

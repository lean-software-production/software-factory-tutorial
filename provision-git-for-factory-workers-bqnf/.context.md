Decision from the play-test review: provision Git in the factory-worker execution environment rather than removing or weakening the first-factory commit requirement.

Outcome:
- Git is installed and usable by Pi workers inside the hardened lesson workspace container.
- Commits land in the active session-local live workspace repository, never the authored template or product repository.
- Configure a deterministic repository-local worker name/email; do not inherit host identity, credentials, signing configuration, remotes, or global Git config.
- Disable signing and avoid any requirement for network access. Review hook behaviour as part of the sandbox threat model.
- A worker commits useful changes when it made them; verification-only/no-op passes do not create empty commits.
- The first-factory prompt/rubric and later commit lessons describe the same real mechanism.

Observed failure: both Pi passes in session tutorial/.tutorial/session-20260829-085045-ae54bea5 reported that the git binary was unavailable. The live workspace repository history retained only its materialisation commit.

Plan using systematic debugging before implementation: trace the worker image/runtime provisioning and workspace mount/ownership boundary; reproduce git-not-found in the same hardened container; then add the smallest provision/configuration change with a failing integration test.

Acceptance:
- A two-pass first-factory run can create an ordinary commit in the session-local workspace.
- Host/product repositories and credentials are inaccessible.
- Repository ownership/safe.directory, identity, hooks, signing, and no-op behaviour are deterministic.
- Restart/reopen preserves the commits.
- Automated sandbox/integration coverage proves the commit landed in the intended repository and nowhere else.

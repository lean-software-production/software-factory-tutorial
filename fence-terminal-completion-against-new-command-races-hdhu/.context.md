## Goal

Prevent terminal input and completion races once an accepted active terminal remains interactive.

## Problem

Keeping xterm live after acceptance creates two races that the old immediate freeze avoided:

1. A learner can press Enter after acceptance before the command-submitted observation reaches workflow state. Continue or scroll completion could complete the earlier accepted attempt during that gap.
2. `completeBlock` may run slow model summarisation while terminal input remains enabled. A new command can start, queue its observation behind completion, then be discarded after the block completes and the PTY retires.

## Work

- Introduce immediate local pending-terminal-activity state when command-entering input is sent, and suppress all browser completion paths for that block until authoritative terminal revision/state catches up.
- Add a server-owned terminal completion fence before departure summarisation. It must stop new input/observations for that block while preserving the live PTY until `block_completed` is durable, then retire it through the existing continuation callback.
- Apply the fence to Continue, scroll completion, and Tutor-tool completion.
- If completion is rejected or summarisation fails, safely release the fence and restore the active terminal.
- Ensure the latest durable terminal submission controls eligibility across restart even when public presentation reopens an idle shell.

## Tests

Cover Enter immediately followed by Continue, command observation queued during slow completion summarisation, tutor/scroll completion paths, failed completion fence release, stale accepted attempt rejection, and no command loss after a rejected completion.

## Deliverable

Commit the narrow race protection with focused deterministic test evidence. Do not redesign terminal transport or add paid/live tests.

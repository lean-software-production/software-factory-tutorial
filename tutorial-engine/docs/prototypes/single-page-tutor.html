Part 2 · Build the factory

Make a boundary you own.

The validator must judge the work without being able to alter it. In this lesson, the harness gathers the evidence and the validator reads it.

About 25 minutesYour editor + terminalOne focused change

The idea

Take away the capability, then supply what it needed.

The validator previously had bash. Its prompt told it not to modify files, but the harness still gave it a way to do so. That is a promise, not an enforced boundary.

Remove bash. The validator can no longer run a test, a quality report, or a diff. The harness runs those commands instead and appends their labelled output to the prompt.

The harness runs the commands and appends their output to the prompt, because the validator can no longer run them itself.

First, the harness runs the checks it knows about. That work is deterministic: quality, tests, and the calculator-only diff.

Then it gives each result a name. The evidence file tells the validator what it is reading and what came before the doer ran.

Only then does the validator read and judge. It can search the calculator if a finding needs context, but it cannot execute a new command.

Boundary experiment

Ask the validator to do the forbidden thing.

A check should show the property it claims to provide. Temporarily add a sentence to validate.md asking the validator to create calculator/proof.txt.

⚗
Intentional failure

Make a prediction before you run it

This is not a normal validation pass. You are testing the boundary itself.

  1. Predict: with no bash, can the validator create the file?
  2. Run ./factory/refactor/validate.sh.
  3. Check ls calculator/proof.txt.
  4. Remove the temporary instruction again.

Expected result: there is no proof file. The prompt asked for one, but the harness did not give the validator a capability that could create it.

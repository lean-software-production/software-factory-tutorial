outcome: "Reflect on the difference between working in a REPL and using a factory."
tutor: |-
  We expect the student to highlight points like:

  * factory requires more up-front investment to build a reliable harness
  * factory burns more tokens
  * REPL requires more continuous attention, where factory can work autonomously for a longer period
  * factory requires being able to express what you want, and how to validate you're getting it
  * factories can tackle bigger tasks
  * factories are great for repetitive, boring or well-established tasks that still need agentic/LLM work to complete

  Wrong answers include:

  * factory requires more trust/faith in the LLM. This is wrong because we never trust the LLM! Factory builds in a validation loop precisely because of this.

  This is a chance for the student to deepen their understanding through reflection: we haven't taught any of these ideas. So we don't need them to hit every point, but we do want to help them to have grasped the general idea.

## Factory vs REPL

When you use a typical coding agent today, you're working in a [REPL](https://en.wikipedia.org/wiki/Read–eval–print_loop) style, where you
have a back-and-forth conversation with the agent.

What are some of the main differences between this way of working and using a factory, do you think?

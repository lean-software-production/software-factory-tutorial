## Goal

Implement a truthful, durable server lifecycle for accepted active editor/terminal attempts and completed practice history.

## Work

- Represent active accepted editor and terminal attempts distinctly from block completion.
- Allow accepted editor evidence to be superseded while active; keep reflection protection.
- Allow later terminal command attempts to receive review after earlier work acceptance. Remove the block-wide terminal review suppression while retaining per-attempt/current-attempt race guards.
- Require the current editor or terminal attempt to be accepted before `completeBlock` is eligible. A newer reviewing/feedback attempt withdraws Continue until accepted again, while durable authored successor material remains revealed.
- On editor acceptance, append a dedicated attempt-correlated editor content snapshot event analogous to `terminal-transcript-snapshotted`.
- Project active accepted editor text without marking the block complete.
- Build completed editor history from snapshot events correlated with accepted attempts; ignore orphan/stale snapshots and select the latest accepted current revision. Do not use the mutable current AttemptStore pointer as the historical body source.
- Continue projecting terminal history from its existing accepted transcript snapshot event; ensure the latest accepted current terminal attempt wins, including after restart.
- Reject new work after the block is no longer active.
- Keep `work_accepted` and successor authored rows idempotent across re-acceptance.
- Base terminal completion eligibility on the latest durable command submission/acceptance, including when restart deliberately hides an unfinished old-session command from public presentation.

## Constraints

Do not retract timeline events or authored successor material. Preserve editor promotion and terminal snapshot privacy. The workspace file/history must match evidence accepted at completion. Do not change reflection semantics.

## Deliverable

Make the attempt/workflow/terminal lifecycle tests pass, then commit the narrow server changes and focused test evidence.
